# Changelog

One entry per release, newest first. "Format" is the project file version the release writes; every release reads all older formats. See docs/releasing.md for how releases are made. Entries before v3.12.0 were written while qtable was developed privately: before each version shipped, the maintainer tried it by hand in "tour" rounds, and older entries mention them.

## v3.12.0 (2026-11-19) — format 12

The first public release. qtable is now free software under the GNU GPL, version 3 or any later version, with its source on GitHub. This release adds an application icon and a macOS app bundle, makes set loading strict about fields it doesn't know, moves the per-machine settings to a versioned file, and settles the command line's words. The project file is unchanged (format 12): v3.11 opens everything v3.12 saves.

- **Licence.** qtable is licensed GPL-3.0-or-later (`LICENSE`). `THIRD_PARTY_NOTICES.md` lists the libraries built into the binaries and the icon's artwork, with their licences, and ships in the zip.
- **An icon and a macOS app.** The icon is a satellite in front of a rainbow, from Google's Noto Color Emoji (Apache-2.0). The zip now holds `qtable.app`, the application with its icon in the Dock and Finder, beside the bare `qtable-gui` and `qtable`. On Linux the window carries the icon, and a desktop file is included in the source.
- **The zip carries the example sets,** in `examples/`, so they open without the source, along with `CHANGELOG.md`.
- **Unknown fields in a set now stop it loading,** with the field named, instead of being dropped silently. A set written by a newer qtable is refused, not half-read.
- **The example sets use format 12,** with named devices, events and arguments.
- **Per-machine settings move to a versioned `config.ron`,** with one section per kind of input. A file from a newer qtable is refused and left as it is. The old `settings.ron` is read once and never changed.
- **The grid's progress mark follows the loop** for clips with an offset loop or an intro before the loop.
- **⌘S and ⌘, no longer clear an unrelated message** in the status bar.
- **The command line.**
  - `start-transport` and `stop-transport` are the transport words; `play` and `halt` still work. A bare `stop` stays an error, since `stop <track>` stops a track. `stop-all`, `quantisation` and `follow-actions` keep their short forms.
  - `qtable --version` and `qtable --help`.
  - When its input is piped, it prints no prompt, and the banner goes to stderr, so stdout holds only command output.
  - It exits with status 1 after any failed command.
- **Transport labels.** Map Mode names the transport controls' location "Transport", and the Control Bar's position field is titled "Transport Position".
- **The layout switches are gone from the release build** (`--collapse-detail` and its kin now report an unknown option). Release builds carry no capture or test hooks; the environment variables qtable still reads are listed in `docs/environment.md`.

## v3.11.0 (2026-11-18) — format 12

Point release: the clip editor. Right-click menus on points, empty lane space, time selections and hits; Insert Shape and Simplify Envelope; zoom on the time ruler; Draw Mode beside Key; and Scene Select at the ends of the list. The project file is unchanged (format 12): shapes write ordinary envelope points, Simplify removes points, and zoom never leaves the window, so v3.10.0 opens everything v3.11 saves and v3.11 opens every older set unchanged.

- **Context menus in the clip editor, by what you click.** A right-click first settles the selection as a left click would, then opens the menu for what is under the pointer. Rows that do not apply are left out, not dimmed; only a row that applies but has nothing to act on yet dims (Paste with an empty clipboard, Clear Envelope with no envelope, Simplify with fewer than three points).
  - **A point** (Envelopes and Overview): Copy, Paste, Delete | Clear Envelope | Draw Mode | Insert Shape | Go to Device. An unselected point is picked alone, so its Position, Value and Curve show in the footer; one of several picked points keeps them all.
  - **Empty lane space:** Paste | Clear Envelope | Draw Mode | Insert Shape, Simplify Envelope | Go to Device. The right-click also puts the insert marker on the nearest grid line, where a left click would (hold ⌘, or Ctrl off the Mac, for the exact tick).
  - **A time selection** (right-click inside it): Cut, Copy, Paste, Duplicate, Delete, then the envelope rows above.
  - **An event hit, and empty space or a time selection on an event row:** the editing rows that apply, then Draw Mode and Go to Device.
  - A choice or switch lane has no shape rows. The ruler, the value scale and the lane headers open no content menu; a header keeps its own. Up, Down, Enter and Escape work in every menu.
- **Insert Shape: Sine, Triangle, Saw Down, Saw Up, Square, Ramp In and Ramp Out**, each with an icon. From a time selection a shape fills the selection on every selected lane that holds a number; from a point or from empty space it fills one grid step (the Grid dropdown's value, or 1/16 with Grid Off) starting at the point or the insert marker. Each is one undo step, on however many lanes. The curve outside the shape stays where it was, joined by a vertical step at each end, so a saw's edge and a square's sides come from the join. The two ramps run from the bottom to the value the line has after the selection (Ramp In) or from the value before it to the bottom (Ramp Out), with no jump at the linked end. On an argument with no envelope, the shape starts one and the rest of the clip keeps the argument's stored value, as in Live. A shape from a point leaves the point where it is, so the line steps from the point's value to the shape's first value. A shape shorter than 16 ticks, or a grid step too close to the clip's end, is refused with a note in the status bar.
- **Simplify Envelope** removes points a straight line makes unnecessary. With a time selection it thins the points strictly inside it on every selected envelope lane; without one it thins the whole envelope of the lane you clicked. It keeps each lane's first and last points, both points of a jump, and both ends of a curved segment, so it never adds a point or changes a curve; a point goes when it lies within the argument's Threshold, or 1 % of its range if larger, of the line between its kept neighbours. On a choice or switch lane it removes only points that repeat the value already held. The status bar reads "Simplified 42 points to 9", or "Nothing to simplify". One undo step. Like Live's, it leaves a dense hand-drawn zigzag as it is: no point of one lies that close to the line between its neighbours.
- **Zoom.** The ruler above the loop brace takes a magnifier cursor. Drag down to zoom in about the time you pressed (one doubling for every 50 px), up to zoom out, and sideways to scroll. Double-click zooms to the time selection, and again to the whole clip. ⌘-scroll (Ctrl off the Mac) zooms about the pointer, scrolling up zooming in; a sideways scroll, or Shift with a vertical one, moves the window; a plain vertical scroll still scrolls the Overview's lane list. Escape during a ruler drag puts the window back, and a right-click ends the drag where it is and opens no menu. The window never goes wider than the clip or narrower than a sixteenth note, and a Start or End flag keeps its own drag. Ruler labels step from bars to beats to sixteenths as you zoom in. Each clip keeps its own zoom while the set stays open, Events, Envelopes and Overview share it, and zooming is never an undo step.
- **The bar-number row of the ruler zooms, and no longer sets the insert marker.** The insert strip below the brace still does.
- **Draw Mode sits beside Key.** The pencil moves to the right-hand group of the Control Bar, immediately left of KEY, as in Live. Every content menu carries a Draw Mode row with B in the shortcut column, ticked while the mode is on; choosing it turns the mode off and closes the menu.
- **Scene Select drops the fraction it owes at the first and last scene.** An encoder mapped to Scene Select at 25 % that spins past the last scene and turns back moves the selection on the usual count of clicks (four at 25 %), as an Int or a choice does. This replaces the v3.10 known limit.
- **Opening a menu keeps the window's scroll positions.** Opening a menu, a dropdown, a chooser or the Settings pane no longer resets a scrolled list behind it to the top (the Overview's lane list jumped to its first lane on a right-click). A device dragged out of the Browser may still do this; it has not been checked.
- **The ruler stays at the top of Events and the Overview.** Scrolling a long list of lanes leaves the bar numbers, loop brace, insert strip and Start and End flags in place, as in Live, so zoom and the flags stay in reach at any scroll position. A plain vertical scroll over the ruler itself does nothing; scroll over the lanes.
- **The point menu's value tooltip stays out of the menu.** No value readout shows while a content menu is open.
- **Known limits.**
  - No zoom keys (+, −, Z, X), no Follow (the playhead can leave a zoomed window and nothing scrolls after it), no pinch, no scrollbar or overview strip, and no scrolling at the window's edge during a drag.
  - No shapes on choice and switch lanes. Insert Shape, Simplify Envelope and Clear Envelope do not appear on event rows.
  - Undo and redo name every one of these edits "Edit Lane".
  - Unlinked rows in the Overview are drawn coarsely at deep zoom.
  - Simplify on a time selection can reshape the line a little just outside the selection, within its tolerance.

## v3.10.0 (2026-11-17) — format 12

Point release: MIDI mapping. A mapping inspector under the list, Latch and Gate for notes and keys, encoder sensitivity, Value Scaling takeover, and mappable event arguments. The project file moves to **format 12**; v3.9.0 cannot open sets v3.10 saves, and v3.10 opens every older set unchanged.

- **A mapping inspector.** Map Mode's list keeps Live's identifying columns (Ch, Note/Control, Path, Name) and is titled "MIDI Mappings" or "Key Mappings", so it fits the Browser at its default width. Select a row (click it, click its control, or press Up and Down in the list, which scrolls to keep it in view) and edit it in a panel pinned under the list: Mode, Takeover and Sensitivity, then Invert, Min and Max. Only the settings that apply to that source and control show; one that applies but not in the chosen mode stays in place, dimmed, and keeps its value. Min and Max have left the row.
- **Latch and Gate for notes and keys.** Latch is what notes and keys have always done: a press flips a switch or sends a number to Max (or Min when it is already at Max). **Gate** follows the pad or key: down goes to Max (On), up goes to Min (Off). It works on switches, numbers, choices, the Activator and event arguments; triggers have no state to hold, so they offer no Gate. A stray release or a repeated press changes nothing. Existing note and key mappings stay Latch.
- **Invert.** An Invert button swaps Min and Max, as Live's context command does. For a switch under Gate it reverses On and Off.
- **Encoder sensitivity.** A relative (endless encoder) mapping has a Sensitivity from 1 % to 1000 %. At 100 % a click moves exactly what it moved in v3.9: a Float by 1/256 of its Min–Max span, an Int, a choice or Scene Select by one unit. A Float step scales with the setting; an Int, choice or Scene Select carries the fraction between clicks, so at 25 % four clicks make one step and at 250 % clicks alternate between two and three. A fraction that could only be paid beyond Min or Max is dropped at the end, so spinning past an end and turning back moves the value on the usual count of clicks (four at 25 %); away from an end, a click back still cancels what the clicks forward owed.
- **Value Scaling takeover**, beside None and Pick-Up, for absolute CCs and pitch bend. When the control and the hardware disagree, the value moves towards the hardware in proportion to the travel left, so there is no jump when you first touch the knob and both reach an end together; once they meet, the value follows the control one to one. Min, Max and Invert apply as they do for None. A choice or a switch has nothing in between to converge through, so it acts as Pick-Up. The curve is a proportional rule from Live's description of the mode, not a measurement of Live.
- **Event arguments map.** A mapped control sets an event argument's value on the Target face and sends nothing; the event's own Bang (itself mappable) sends the value. A Float or Int with no range learns 0–1 or 0–127, editable in the inspector. The rows read "<event> <argument>". A parameter with several arguments now names each row "<parameter> <argument>" ("Position x"), which renames rows that read "x" before.
- **Takeover no longer applies to the Activator**, whose Min and Max are an input window, not an output range. A stored Pick-Up on one is ignored, so the mapping follows the control directly. Takeover is also ignored on Scene Select and on triggers, as it was in effect before.
- **Format 12.** Gate, Value Scaling, sensitivity and event-argument mappings are the only additions, and each is written only when used. A set saved by v3.10 with none of them differs from its format-11 save by the version line alone. An older reader refuses a format-12 file by version.
- **The mapping list stays inside its frame.** The title strips and the selected row no longer paint over the 1 px stroke around the Browser in Map Mode, at any width; the inspector below it sits inside the stroke too.
- **Known limits.**
  - A Gate held when Map Mode is switched on, or whose release is lost with its port, stays at Max until the next press and release.
  - Each Gate press and release is its own undo step, so a long performance fills the 200 steps sooner.
  - An encoder mapped to Scene Select keeps the fraction it still owes when you spin past the first or last scene, so at 25 % reversing there takes up to 3 extra clicks before the selection moves.
  - Value Scaling's curve has not been compared with Live's.
  - A file stamped format 11 that holds format-12 spellings (Gate, Value Scaling, a sensitivity, an event argument) loads, though v3.9.0 would refuse it.
  - A three-line Path in the inspector, from a very long track and device name at the default Browser width, is clipped at the bottom of the panel.
  - Not built: controller feedback (LEDs, motor faders), 14-bit CC, NRPN, note ranges, pitch bend beyond what exists.

## v3.9.0 (2026-11-15) — format 11

Point release: Shortcuts. Space plays and stops, ⌘S and ⇧⌘S save, ⌘, opens Settings, and shortcuts work from inside a field; open menus take the keyboard. The project file is unchanged (format 11), and v3.8.0 opens everything v3.9.0 saves. Accepted on 2026-11-15 after two tour rounds and their fixes.

- **Space starts and stops the transport**, when nothing else has taken the key. A text field that has the keyboard types the space, and so does a value you have typed but not yet entered. An open route list still uses Space to pick a row. A held Space, and Space with Shift, Alt or Cmd, do nothing. Key Map Mode never maps Space.
- **⌘S saves and ⇧⌘S opens Save As** (Ctrl-S and Ctrl-Shift-S off the Mac), wherever the focus is. Typing in a field is entered first, as a click elsewhere would enter it, and each entry is an undo step of its own.
- **A rejected value blocks saving.** If the engine refuses what you typed (a tempo of "fast", a name the engine refuses), the status bar shows the error and nothing saves, so the file never disagrees with the screen. The refused field stays as a draft, so every further ⌘S or ⇧⌘S refuses too until Escape drops it. This holds while a scheduler failure is showing in the status bar.
- **⌘, opens Settings** (Ctrl-, off the Mac). Pressed again, the pane stays open; the Settings button still toggles. Typing is entered first; a rejected value reverts to what the field held before, and Settings opens.
- **Shortcuts work from inside a field.** ⌘- and Ctrl-keys no longer type their letter into a text field (⌘A, ⌘C, ⌘V, ⌘X and undo still work there). After ⌘S, ⇧⌘S or ⌘, the field lets go of the keyboard, so Space plays. Enter does the same once the value is accepted; a rejected value keeps the keyboard in the field so you can put it right.
- **Menus take the keyboard.** While a right-click menu, the Sections menu or a lane chooser is open, Up and Down move the highlight, Enter chooses, Escape closes, and other plain keys, Space among them, do nothing behind it. ⌘-shortcuts still work.
- **The device Activator's focus outline is round.**
- **Release tool.** `tools/release.sh prepare vX.Y.Z` checks the tree, the version files and the CHANGELOG section, runs `./check.sh`, then commits and makes an annotated tag that records the check and the tested tree. `verify <tag>` runs the same checks without building. `build`, `package` and `publish` refuse a tag without that record (`--unrecorded` accepts tags made by hand, as v3.8.0 and earlier were), release notes now refuse a missing CHANGELOG section, and `publish` compares the tag with the one on origin before it builds (docs/releasing.md).
- **Known limits.** Ctrl-S, Ctrl-Shift-S and Ctrl-, have not been tried on Linux. Space still reaches the transport while the Settings pane is open, and iced's own drop-down lists (Quantisation, MIDI port) have no keyboard control.

## v3.8.0 (2026-11-12) — format 11

Point release: Undo. ⌘Z and ⇧⌘Z (Ctrl-Z, Ctrl-Shift-Z and Ctrl-Y off the Mac). The project file is unchanged (format 11), and v3.7.0 opens everything v3.8.0 saves. Accepted on 2026-11-12 after four tour rounds and their fixes.

- **Undo and redo.** One history per set, owned by the engine, so the GUI and mapped controllers share it. It keeps 200 steps; saving keeps it, opening or creating a set clears it. Everything saved in the set is undoable (tracks, clips, hits, envelopes, devices, Targets, values, routes, tempo and the rest), except a group's fold and a device's expanded flag, which an undo leaves as they are. Playback, selection, scroll and settings never enter the history. The status bar names each step ("Undo: Rename Clip").
- **What makes a step.** One thing you do makes one: a whole fader, dial or number-box drag (a Target value, a track's Delay), a held arrow key, a typed value and its Enter. Typing a name and then clicking elsewhere makes two. A mapped controller's moves of one control join one step until something else makes a step, as in Live (2026-11-11); two controls moved in turn make a step for each move, undone newest first (A, B, A, B undoes B, A, B, A), as in Live. A drag that ends where it began leaves no step.
- **Mappings stay outside the history**, as in Live (tour round 2). Mapping or unmapping a control makes no step, and an undo or redo leaves the mappings as they are. A mapping still marks the set unsaved. A mapping that goes with its control comes back with it: delete a mapped track and ⌘Z, and the knob drives it again (tour round 3).
- **During playback.** The transport keeps running. A clip the undo removes stops; a clip it brings back waits to be launched, as in Live 12.1. A changed stored value reaches receivers as a manual change (a playing envelope driving it becomes overridden), and a changed tempo re-times the clock.
- **Unsaved marker.** The title dot follows the content: undo back to the saved state and it clears; redo past it and it returns.
- **Typing.** ⌘Z with unsaved typing in a field drops the typing and undoes one step, as in Live.
- **Cost, as measured on 2026-11-11**: 200 steps added about 15 MB of resident memory on an ordinary set and 125–137 MB on the dense 64-track, 1,025-envelope set, where repeated undo and redo reached about 210 MB in all. In the paired headless run against v3.7.0 on AC power, hits met their send limits in every arm. Under nine-source controller load this build splits value batches per source (about 520 a second against 58), and the slowest jumps completed some 100–150 µs later than v3.7.0's (about 830 against 700 µs); undo and redo at 60 pairs a second added nothing I could distinguish on arm g, and cost about 1 ms a call on the dense set, whose jumps already missed their targets on v3.7.0.
- **Known limits.** Under nine-source controller load the slowest jumps complete about 100–150 µs later than on v3.7.0 (accepted on 2026-11-11). Holding an arrow key while clicking a toggle puts the toggle in the key's step (accepted in tour round 1); a dropped pointer release can merge two clicks. Not undoable yet: a mappable Undo control, `undo` in the CLI, `/qtable/undo` over OSC.

## v3.7.0 (2026-11-08) — format 11

Point release: Session View. Receive-time launch recovery, scene selection and moves, nested groups, multi-track drag and Detail View navigation. Accepted on 2026-11-08 after the completed tour and its six fixes.

- **Receive-time launches.** A quantised launch received before a boundary can recover that boundary when dequeued within **2 ms**, preserving FIFO order and preceding value batches' enqueue-time effect. This addresses v3.6's scheduler-queue boundary loss under controller load: the paired headless measurement on 2026-11-07 recorded 18/18 intended-bar misses before versus 0/18 after in the core loaded runs. Recovered first sends were still roughly 0.7 ms late. This is **no first-send latency guarantee**: already-sent boundary hits cannot be withdrawn, holds can outlast grace, owner stalls and post-boundary value batches can prevent recovery, and mixed unquantised rows fall back as a whole. CC input still uses the continuous wake interval (up to 16.7 ms), including mapped launches. Dense-project timing limits remain.
- **Scenes.** Shift selects a range; Command-click on macOS or Ctrl-click on Linux toggles individual scenes. Delete/Backspace or the scene menu removes the selected rows atomically, keeping at least one scene. Drag selected scene bodies to move their rows together in project order; clips, empty slots and stop flags stay aligned, with one full-width insertion line. Selection survives the move. The horizontal selected-scene row intentionally follows the **last clicked scene** after range/additive selection, unlike Live's initially clicked row (2026-11-07). Repeated scene launches now retain ownership of reused pending clips so Cancel Scene Launch cancels them too, while started clips and later manual launches remain intact.
- **Stop feedback.** A fired empty stop slot flashes its own square while waiting for the quantised stop; the playing triangle stays green until playback stops. Scene launches briefly flash all enabled empty stop squares, including inactive tracks and Group summaries; only destinations with pending stops continue pulsing. Disabled stop cells stay absent. Lower track-stop buttons stay steady.
- **Nested groups.** Groups can contain Groups, with ancestor header bands, independent folds, retained hidden selection and recursive slot/activity summaries. Group launch and Stop reach descendant clip tracks once; ancestor Activator and Solo cover their descendants. Routes and relative paths resolve through the hierarchy. Group Tracks wraps sibling subtrees; move, Ungroup and Delete preserve the forest and prune emptied ancestors. Joining changes only the moved root to Group routing; promotion preserves explicit routes, while inherited routes follow the surviving parent or Main. Copy, Paste and Duplicate carry whole subtrees, hidden members included, with fresh IDs and no copied mappings; surviving controls keep their mappings. Selected Group bands follow their title highlight, and Group Tracks sits immediately above Ungroup Tracks in the menu.
- **Multi-track drag.** Move selected tracks and Group subtrees together in project order, with selected ancestors carrying descendants once. Shift selects a visible range; Command/Ctrl toggles headers. Dragging a selected title retains the set; a plain click collapses it on release. The narrow neutral insertion line begins at the destination depth and continues through the body and mixer. A folded Group's left half inserts before it; its right half inserts as the first child, keeping the fold. Held-edge scrolling reveals horizontal track destinations beside Outputs/Main and vertical scene destinations; preview and drop use the same placement, and pinned headers remain readable while scrolling.
- **Detail View.** Single clicks select while a collapsed panel stays collapsed. Double-click track, Group or Output titles, an existing clip, a scene body or Main's title to reveal the corresponding view. Double-click an empty slot to create a clip and open Clip View. An open panel continues to follow selection; fold buttons keep their folding action.
- **Reorder keys.** Ctrl+Left/Right reorders tracks and Ctrl+Up/Down reorders scenes on the Linux modifier path; macOS keeps Command+Arrow and ignores Ctrl+Arrow. Focused fields retain their keys. Platform-path regressions pass, but native Linux key delivery and desktop interception remain deferred to the dedicated Linux testing pass.
- **Format 11.** Every earlier project (formats 1–10) opens with its track order, IDs, routes, folds and mappings preserved. Saves now support nested groups. A set saved in format 11, including a flat set, cannot be opened by v3.6.0 or earlier. Try development builds on copies (docs/releasing.md).

## v3.6.0 (2026-11-04) — format 10

Point release: Remote control. Map MIDI controllers and computer keys to qtable's controls, as in Live's MIDI and Key Map Modes. Project files move to **format 10**, which stores the mappings. v3.5 and earlier can't open a set once this release saves it. Accepted on 2026-11-04 after three tour rounds.

- **MIDI Map Mode** (⌘M, or MIDI at the top right). Mappable controls show a blue overlay. Click one, then move a knob, press a pad or bend the wheel to map it. The overlays label each mapped control with its source. Controls don't operate while Map Mode is on.
  - **What maps:** Mixer Volume, Pan, Activator and Solo; every numeric Target argument; event bangs; tempo and the transport buttons; whole clip and group slots; scene launch buttons; track stop buttons; and track headers, which select the track.
  - **The scene strip** under Main appears in Map Mode. It holds Scene Launch (launches the highlighted scene and moves the highlight down one), Cancel Scene Launch, Scene Up, Scene Down and Scene Select.
    - Scene Select spans every scene: an absolute CC spreads across them, an encoder steps and stops at the ends, and a note or key wraps.
    - Cancel Scene Launch drops the triggered scene's clips that are still waiting for their quantize points. A playing clip keeps playing and a stopped track stays stopped.
- **Key Map Mode** (⌘K, or KEY). Map any printable character, case kept (`a` and `A` differ), including digits, symbols and punctuation. Named keys and whitespace don't map, and ⌘, ⌥ and ⌃ shortcuts always reach qtable even when their letter is mapped. A focused text or number field keeps its keys.
- **The mapping list** replaces the Browser in Map Mode, filtered to the active mode. It has Live's columns (Ch, Note/Control, Path, Name, Min, Max) plus Takeover and Mode.
  - **Min and Max** fit each control's kind: values, Off/On, enum choices, or the Activator's window. They drag like other number fields.
  - **Mode** is Absolute or one of Live's relative encodings. The relative curve follows Live 12's measured acceleration.
  - **Takeover** is set per mapping: None (the default) or Pick-Up.
  - **One source per mode:** a control holds one MIDI and one key mapping, and learning a new source replaces the old one. One source may drive several controls.
  - **Delete** clears the selected mapping, picked in the list or on its control.
- **Mapped behaviour matches a click.** A mapped launch or empty-slot stop moves the selection to that cell. A CC on a slot fires as it crosses 64. Mapped bangs flash orange. A mapped value overrides that parameter's automation, as a mouse edit does.
- **Settings.** A Settings button after Save As opens a Settings pane. Its MIDI tab lists your input ports, each with a Remote switch remembered on this machine.
  - **Hot-plug:** a controller switched on while qtable runs appears and connects within about a second, and one switched off shows as disconnected.
  - **Top right:** only KEY, MIDI and a bare square that flashes on MIDI input.
- **Number fields drag like Live's.** Press a number field and drag up to increase or down to decrease, Shift for finer; a click still selects the value for typing. Every Number field gets it, including the Map Mode list's Min and Max. Double-click returns a field to its default where it has one (now also point Value and Curve, Target stage settings, and track Delay and Latency).
- **Engine.** Remote input is a client of the same command layer as the GUI (new `qtable-remote` crate, depending only on the engine and `midir`). Input is bounded and ordered, and several parameter writes from one controller pass reach the engine as one batch.
- **Known limits** (accepted on 2026-11-03):
  - **Boundary launches:** with knobs moving, a mapped launch arriving within about a millisecond before a quantisation boundary can take the next boundary instead.
  - **Dense projects:** sets with hundreds of envelopes exceed the timing targets with or without controller input.
  - Up to 8,000 CC/s with 320 mappings, v3.3's reference workload met its send targets.

## v3.5.0 (2026-11-03) — format 9

Point release: Groundwork and polish. Live's segmented time fields, Go to Device in lane menus, a regrouped Target argument inspector that shows only what applies, a steady clip-editor footer, one menu kind for every popup list, and engine groundwork for v3.6 Remote control. Project files are unchanged (format 9). Accepted on 2026-11-03 after two tour rounds.

- **Segmented time fields.** Every bars.beats.sixteenths field (clip Start, End, Position, Length and unlinked Follow Time; the Envelopes region fields; point Position; Scene Follow Action Time) works like Live's. Click a segment to select it, type to replace only that segment, press Up/Down to nudge it with carry into the next bar or beat, drag vertically to change it, and press Left/Right to move between segments. Paste or Select All still takes a whole value. Blank parts read as zero (as 1 in a position), so `5.` and `5.2.` are accepted. A length or time at its floor stays put rather than stepping to zero. This fixes the Length field bug found on the v3.4.1 tour.
- **Go to Device** in the right-click menus of event rows and hits (Events and Overview) and of envelope rows. It opens the Track tab and reveals the event, the parameter or the Mixer's Volume on its device.
- **The Target argument inspector** is regrouped in three: Name | Type and Default | Control; then Range | Min | Max on one row; then Send, with Threshold. `+` follows the last argument tab. It shows only what applies to the chosen kind: Range, Min, Max and Threshold appear only for a Float or Int with a Slider, Dial or Number box, and Every Frame shows Threshold disabled. A String Enum option hides its Value, since a String sends its Label.
- **Threshold applies only where it can.** The scheduler ignores a stored Threshold on Toggle, Enum, Text, Bool and String arguments. The value stays in the file and takes effect again if the argument returns to a continuous control.
- **A steady clip-editor footer.** The footer under Events, Envelopes and Overview keeps one height across selections, reserving room for the clip's tallest hit, so the editor above no longer jumps. The hit inspector drops its path field (an event's path is edited on its Target device), wraps arguments into columns without scrolling, and lines up "Hit arguments" and Remove hit with the fields.
- **One menu kind.** Context menus, choosers and popup lists share the same ink, rows, hover and checks. A menu near a window edge opens on the side with room instead of clamping, and long lists scroll at a capped height.

## v3.4.0 (2026-11-02) — format 9

Point release: Loops and regions. Clip Start and End markers separate from the loop brace, envelopes that unlink and loop on their own, time selections and region edits in the clip editor, Draw Mode, and Live's insert marker and playhead. Accepted on 2026-11-02 after two tour rounds.

- **Clip markers.** A clip has Live's four markers: **Start**, **End**, and a **loop brace** (Position and Length), each independent, so a clip can play an intro into a shorter loop. Set them in the clip box (Start, End, Loop, Position, Length; Set buttons take the playhead, rounded to the global quantisation) or drag the Start/End flags, the brace ends and the brace body on the ruler. Alt-Left/Right moves Start and End together by the grid step. Length always means the brace's length, with Loop on or off. Content outside the markers is kept, as in Live.
- **Loop brace.** Inward triangles mark both ends, resize cursors show on the ends and flags, a move cursor on the body, and the brace fills light blue while dragged. qtable fills the brace with the clip (or lane) colour and keeps the Start/End flags above it, where Live draws a grey outline with the flags below.
- **Unlinked envelopes.** In an envelope's one-lane view, **Linked → Unlinked** gives that lane its own Loop, Start, End, Position and Length, copied from the clip's; relinking keeps the points. An unlinked lane plays its own loop from launch, can be longer than the clip's loop, and runs on across the clip's wraps; with its Loop off it holds its End value while the clip continues. Unlinking while the clip plays keeps the lane's phase. A legato take-over gives an unlinked lane the phase it would have had if launched with the clip, as Live does; a plain launch restarts it at its own Start. In All lanes an unlinked lane shows a broken-chain badge, a read-only projection of its curve and its own playhead; the one-lane view shows its own playhead too. Paste in All lanes skips unlinked envelopes and says so in the status bar.
- **Insert marker and playhead.** A click on the background or the strip under the brace places Live's insert marker (blue triangle; "Insert Mark" in the status bar), separate from the white playhead, which stays where playback stopped. Left/Right move it by the grid step and Home/End jump to Start/End. Paste lands at the insert marker.
- **Time selection and region edits.** Drag across lanes for a time selection; click, Shift-click or ⌘A to pick hits and points. Delete, ⌘C/⌘X/⌘V and ⌘D work on the selection, and Alt-drag copies it. A time range between points copies the curve's shape, adding points at the range edges, so repeated ⌘D builds Live's sawtooth; a curved segment cut by the range keeps its shape to within 3% of its range. Picked points at beat zero delete, cut and move like any other.
- **Draw Mode.** B (hold for momentary) or the pencil switch in the transport. Draw steps on an envelope at the grid, or freehand with ⌘ or with the grid off; draw hits on an event lane, and click a hit to delete it. Shift draws a tenth of the change.
- **Points and segments.** A click on a point selects it and fills Position/Value/Curve; a second click on it, or Delete/Backspace, deletes it. Hovering near a segment (up to 16 pt in the one-lane view, a quarter of the row in All lanes) highlights it and both its points, and a drag moves both.
- **Info View** help for the Start and End markers, the loop brace and its ends, and the envelope line, in both views.
- Clicking an event in the **Control chooser** adds its lane if it has none and selects it in All lanes.
- **Format 9** stores the four clip markers and each envelope's optional own region. Older sets upgrade on open, with Start and loop start at zero and End and loop end at the old length; sets saved by this build need a format 9 reader.
- Playback runs on one clip timeline shared by hits, envelopes, jumps, legato and follow actions; envelope frames sample without allocating, frame wakes search only changing segments, and commands that don't touch automation skip its resync. Region edits, Draw Mode and paste share one atomic range edit in the engine.

## v3.3.0 (2026-10-22) — format 8

Point release: Envelopes. Clip automation of Target parameter arguments and Mixer Volume, the clip editor's all-lanes overview and device/control choosers, and event lanes that behave like tracks. Accepted on 2026-10-21.

- **Clip envelopes** automate individual Target parameter arguments and Mixer Volume. Event and envelope lanes share one ordered list. Float values interpolate with curvature; Int values round to whole numbers; Toggle and Enum values hold until their next point. Two points at one time make a jump.
- Playback sends ramps on each output's Frame Rate and sends launches, discrete changes, point-pair jumps and loop wraps at their own musical times. A multi-argument parameter sends its whole message, with the other arguments sampled at the same instant. Mixer Mapping, Threshold, Budget, Bundle and track/output delay still apply; On Release affects manual drags, not envelope playback.
- Manual changes override just that argument. In On Release, the control previews your drag while the receiver keeps following the curve; releasing takes over. **Re-Enable Automation** in the Control Bar, the control's menu, a lane header menu or a grey lane-header dot restores playback. Launching a clip containing that envelope also restores it at the launch boundary. Stopping holds the last value; a manual edit or reset replaces it, including a reset to the saved base value.
- Automated controls show a red dot while following and a grey dot while overridden. Held values after Stop have no control dot. Target controls, Mixer Value and the strip fader share this behavior; manual changes show promptly while the scheduler publishes its next snapshot.
- **All lanes** shows event hits beside curves, live values and red/grey automation dots. Empty envelopes have a dotted current-value guide. **+ Lane** lists New Event, each Target and Mixer; existing lanes are marked and disabled. Absolute-path events remain available through New Event and path editing, and through the Control chooser for existing lanes.
- **Device and Control choosers** open one envelope at full height, with its range, live value, automation state, faint curves from the other lanes and event ticks. Int envelopes also show a faint rounded staircase. Choose an argument without a lane and click to start one. **Only show adjusted envelopes** filters the chooser; each clip remembers its view. Choosing an event returns to All lanes with that event lane selected. Chooser lists currently open at the pointer.
- **Show Envelope** in a Target or Mixer control's menu opens that argument in Clip Detail. It works on the selected clip on that control's track only, and is greyed otherwise, even if another clip is playing. It neither creates nor selects a clip.
- Click to add a point, click a point to delete it, or drag points and segments. Dragging past neighboring points removes them; dragging back before release restores them. Landing exactly on a neighbor makes a step. Shift refines continuous value drags; Command bypasses the time grid; Alt-drag bends a segment and Alt-double-click straightens it. Escape, focus loss or a changed clip/view cancels the pending edit.
- The selected point has **Position, Value and Curve** fields. Typed Position stays for now and uses bars.beats.sixteenths from 1.1.1. Value uses the argument's own control, including Enum choices; Curve stays visible but disabled for discrete values and the last point. Enter or click outside commits, Escape restores; rejected values stay in their field with the reason in the status bar. Add or drag a point to select it for typed editing; a plain point click deletes it.
- Lane headers select and Shift-select ranges like tracks. Drag a selected range as one block, with an insertion marker, or use **Copy, Paste and Delete**. Cross-track paste carries definitions; content beyond the destination clip's length is trimmed and reported in the status bar. Existing destination envelopes win, event lanes merge, and identical copied hits do not multiply. **Lane Duplicate was removed**; Command-D on a lane header does nothing. Track Duplicate is unchanged.
- **Format 8** stores mixed event/envelope order, points and curvature. Older sets, including format 7 Targets, upgrade on open; sets saved by this build need a format 8 reader. Playback values and overrides stay out of saved sets. Changing argument ranges or controls conforms points, Enum changes preserve choices by wire value, and removing an argument or device removes its envelopes.
- Numeric controls are ready for replacement typing when selected by click or Tab. Enter commits and readies another replacement; Escape restores the value and keeps it ready to type. Selected controls show no text highlight or caret; typing shows a caret that fades white/red. Tempo uses the shared transport surface. Text and Path inputs keep their usual editing behavior.
- Up/Down nudges selected Number boxes, Sliders, Dials and Mixer faders, with native key repeat; Shift makes continuous steps and drags four times finer. Typing drafts wait for commit before nudging. On Release holds a keyboard preview until key release. Int Number boxes retain focus across nudges; scrolled Int Dials no longer jump on click or drag. Enter activates selected toggles once per press.
- Shared parameter gestures, field ownership, lane moves, curve drawing and stepwise file migration consolidate the underlying implementations. The Target face continues to supply the hands-on controls.

### Known limitations

- **Muted tracks still send envelopes.** Currently source Activator and Solo do not suppress parameter automation, including exact jumps; destination Activators and device enablement still gate sends.
- **Large launches start late.** Launching or recalling a scene that drives many automated parameters at once (hundreds) sends that launch's first hits late: every parameter is prepared and its value sent before the hits that depend on it. The hits after that first beat play on time. As measured on 2026-10-20 with 256 parameters, the first beat was about 8 ms late from stopped with Bundle Off, about 4 ms with Bundle On, and a few milliseconds on a scene change. Bundle On shortens sending, not preparation. The timing targets cover ordinary playback, not large scene recalls.
- **Automation timing is accepted for tested workloads, with exceptions.** On the maintainer's Apple M2 Mac with two outputs, jumps and the hits around them met their targets, but a few hits away from any jump arrived up to 0.14 ms late against the 0.1 ms target, with no established cause. More outputs, real networks and other machines aren't verified.
- **Commands can wait for an earlier frame.** So that an edit or transport command can't erase automation already due, it waits until earlier parameter frames have gone: up to about 2 ms as measured, 4 ms at most by design. A launch pressed during that wait goes correspondingly later.

### v3.2 Devices

- **Device chain** in each track's Detail View, modelled on Live's: drop devices from the **Browser**, reorder, copy, paste and delete them, fold them, switch them off. Devices sit 8 px apart on a darker chain background. Each argument has a **Control** (Slider, Dial, Number, Toggle, Enum, Text) limited by its type, an optional range, a default, and a threshold for parameters. Toggles send 0/1 on Int and Float, and T/F on Bool. Unnamed arguments read "Arg 1", "Arg 2". Targets go on tracks only.
- **The face**: collapsed, a Target shows a generated control panel. It has EVENTS and PARAMETERS headings, one cell per entry with a title strip, icon-only bang buttons for events, and labels laid out to one shared guideline (measured from Live 12). Clips automate what the face shows. Pressing a bang fires its event once, including while stopped.
- **Expanded**, the Target reads left to right: the entry editor (Target Path, + Event / + Param, Name, Event or Param Path, Send, Delete), the face (click a title or any control to select it), and the argument inspector (one argument at a time on tabs). - **Clips on Targets**: clip lanes are a Target's events, and hits carry their arguments. Event fields have current values, which the bang sends; defaults seed new hits.

- The Detail View holds devices at a fixed height in device mode (Live's 169 px body). Clip and Scene modes stay resizable.

### v3.1 Output

- Output stage: each output and Main with a destination now sends parameter changes on a shared control-frame grid, keeping only the latest value between frames. **Frame Rate** (1–60 Hz, default 30) lives in Output/Main Detail beside Latency (Main: Track Delay), above Budget, Bundle and Refresh. Continuous edits wait for the next frame; clip events keep their own deadlines and never wait for a frame.
- **Every Frame** replaces Stream in **Send Mode** and follows each recipient output's Frame Rate; the per-parameter Rate field is removed. Track delay and output latency still shift values and the tail after Stop. Opening a v3.0 set with a differing enabled Stream rate shows the notice "Every Frame now follows each output's Frame Rate" in the status bar and CLI.
- **Threshold**, paired with Send Mode, suppresses small changes in sent units after Mapping (default 0 = any change). The final resting value still sends after one quiet eligible frame. Threshold is disabled in Every Frame and keeps its value.
- Output and Main Detail gain **Budget** (10–10 000 messages/s), **Refresh** (0.1–10 s) and **Bundle**, all Off by default. Budget gives clip events priority, then parameter changes, then repeats; changes wait for room and repeats are skipped. Clip events are never merged, deferred or dropped by the Budget. Budget and Refresh remember their values while Off.
- Refresh resends enabled parameter values across its interval, spread over frames, while playing or stopped. Bundle packs frame messages and clip events due at the same instant into separate immediate OSC bundles of at most 1472 bytes; a message too large for a bundle goes plain and raises one notice per output per session.
- Output and Main strips gain a meter-only **Throughput** strip with messages/s, orange while parameter changes wait for Budget room. Track and Group delay fields move into their Detail Mixer panels. The Detail **Throughput** section shows Messages/s, Packets/s, Bytes/s, Merged/s, Deferred/s, Skipped/s, Oversize and Frame late; the CLI also reports throughput. The meter uses Budget when on, otherwise compares with the busiest destination.
- Frame Rate stays capped at 60 Hz: shared frames reduce scheduler load, but measurements still found a rare sub-millisecond clip-send stall. The cap has not been raised.
- Known difference from Live: a stop or relaunch pressed less than 2 ms before a bar line lets the stopping clip's bar-line events go out, where Live would suppress them.
